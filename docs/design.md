# Snake 项目设计

## 目标

Snake 是一个基于 Bubble Tea v2 和 Lip Gloss v2 的终端贪吃蛇游戏。项目优先保证结构清晰、方便扩展，并让游戏核心逻辑不依赖具体 TUI 框架。

## 架构分层

```text
cmd/snake
  程序入口，只负责启动 TUI 程序。

internal/game
  游戏领域层，负责蛇、食物、地图、碰撞、得分、暂停和重开等纯规则。
  这一层不依赖 Bubble Tea 或 Lip Gloss，后续可以复用到 Web、测试、AI 控制器等场景。

internal/tui
  终端交互层，负责 Bubble Tea 的 Model、消息、按键、定时器和窗口尺寸适配。
  它调用 internal/game 驱动游戏状态变化。

internal/ui
  终端渲染层，负责 Lip Gloss 样式、棋盘绘制、彩色蛇身、状态栏和帮助文本。
  这一层只把 game.State 渲染成字符串，不修改游戏规则。
```

## 核心模型

- `game.Point`：棋盘坐标。
- `game.Direction`：蛇的移动方向，负责反向移动保护。
- `game.State`：当前棋盘、蛇身、食物、分数、游戏状态和帧号。
- `game.Engine`：封装随机数和规则操作，提供 `Tick`、`Turn`、`TogglePause`、`Reset` 等方法。
- `game.EnemyState`：敌蛇快照，供 TUI 渲染层读取。

## 交互设计

- 方向键或 `WASD` / `HJKL` 控制方向。
- `Space` 或 `P` 暂停和继续。
- `R` 重开。
- `Q`、`Esc` 或 `Ctrl+C` 退出。

## 视觉设计

- 棋盘使用 Lip Gloss 绘制边框和背景。
- 食物使用醒目的红粉色。
- 蛇头和蛇身分开渲染。
- 蛇身颜色由帧号和身体索引共同决定，tick 推进时颜色沿蛇身流动，形成游动变色效果。
- 敌蛇使用红橙色流动效果，散落方块使用绿色。
- 右侧侧栏展示 Top 10 分数、敌蛇数量和下一条敌蛇生成倒计时。

## 敌蛇规则

- 游戏运行后每约 30 秒尝试生成一条敌蛇。
- 最多同时容纳 6 条蛇：玩家 1 条，敌蛇最多 5 条。
- 敌蛇通过 BFS 寻路，在食物和玩家头部之间选择目标，阻碍玩家吃食物或主动进攻。
- 敌蛇撞到玩家头部时游戏结束。
- 敌蛇撞到玩家身体、墙或其它敌蛇时死亡，并把身体散落成可吃方块。
- 玩家吃食物或散落方块都会加分并增长身体。

## 扩展点

- 新增难度：调整 `game.Config` 的地图大小和 tick 间隔。
- 新增关卡：在 `game.Engine` 中加入障碍物集合。
- 新增 AI：实现外部控制器，调用 `game.Engine.Turn`。
- 新增渲染主题：扩展 `internal/ui` 的调色板和样式，不影响游戏规则。

## 局域网联机设计

### 目标

- 默认不带参数启动时继续运行现有单机模式。
- 使用 CLI 参数切换局域网联机模式。
- 第一阶段只支持 2 人共享同一张地图。
- 第一阶段保留现有食物、敌蛇、掉落、暂停、重开和总分规则。
- 第二阶段再增加房间列表和断线重连。

### 启动方式

- `snake`：单机模式。
- `snake --host`：开房并作为房主进入游戏。
- `snake --join 192.168.1.10:7777`：加入指定房主地址。

### 总体架构

联机模式采用房主权威模型。

- 房主进程独占游戏引擎，负责唯一的 `Tick` 循环。
- 房主统一处理食物生成、敌蛇移动、碰撞结算、得分和游戏状态切换。
- 客户端不执行本地规则模拟，只发送输入并渲染房主广播的状态快照。
- 单机模式继续直接在本地驱动 `game.Engine`，不经过网络层。

这样可以最大程度复用现有分层：

- `internal/game` 继续只负责纯规则。
- `internal/tui` 负责按运行模式接入本地引擎或远端会话。
- 新增网络层负责消息协议、连接管理和房间会话。

### 第一阶段范围

第一阶段只做最小可玩双人联机：

- 2 名玩家共享一张地图。
- 房主为玩家 1，加入者为玩家 2。
- 两名玩家都能控制各自蛇移动。
- 地图尺寸、tick 节奏、食物、敌蛇和掉落由房主统一决定。
- 任意玩家死亡时，整局进入 `GameOver`。
- 分数先保留为房间共享总分，不拆分个人计分面板。

第一阶段明确不包含：

- 房间发现。
- 房间列表。
- 断线重连。
- 观战模式。
- 多于 2 名玩家的房间。

### 第二阶段范围

在第一阶段稳定后，补充以下能力：

- 房间列表。
- 局域网房间发现。
- 断线重连。

### 游戏规则调整

当前引擎只有 1 条玩家蛇和多条敌蛇。联机后需要扩展为 2 条玩家蛇共享棋盘。

规则保持最小变化：

- 两名玩家都遵守现有方向变更和反向移动保护规则。
- 两名玩家都可以吃食物和掉落。
- 任意玩家撞墙、撞自己、撞对方身体时，整局结束。
- 两名玩家头对头进入同一格时，整局结束。
- 两名玩家头部对穿时，整局结束。
- 敌蛇继续由房主驱动，仍可攻击玩家。

### 引擎改造方向

联机模式下，`game.Engine` 需要从单玩家模型扩展为双玩家模型。

建议改造方向：

- 将当前单一 `snake` 状态升级为两个玩家槽位。
- 将 `Turn(direction)` 改为按玩家编号提交输入。
- `Tick()` 内先收集两个玩家的下一步意图，再统一结算本帧结果。
- `State` 从单蛇快照扩展为双玩家快照。
- 房主模式下，状态快照作为网络广播源；客户端模式下，状态快照作为渲染输入。

统一结算的重点是避免按先后顺序移动导致不公平或出现错误碰撞结果。

### TUI 改造方向

单机模式下，TUI 继续直接驱动本地引擎。

联机模式下，TUI 只负责：

- 采集按键输入。
- 将方向输入发送给房主。
- 接收并渲染最新状态快照。
- 渲染连接状态、等待加入和断线提示。

需要注意的差异：

- 联机模式下不能由本地窗口尺寸直接触发 `Engine.Resize`。
- 地图尺寸必须由房主决定，并在加入时同步给客户端。
- 客户端终端过小只影响本地显示，不应改变房间地图。

### 网络协议

第一阶段优先使用 `TCP + 长度前缀 JSON`。

原因：

- 局域网内延迟低，实时性足够。
- 实现简单，便于排查问题。
- 连接语义明确，适合后续增加重连逻辑。

建议消息类型：

- `Join`：客户端请求加入房间。
- `Welcome`：房主返回玩家编号、地图尺寸、tick 间隔和初始快照。
- `Input`：客户端提交方向输入和输入序号。
- `Snapshot`：房主广播完整状态快照。
- `Command`：暂停、重开、退出等控制消息。
- `Ping` / `Pong`：第二阶段用于连接健康检测。

第一阶段优先保证正确性，先发送完整快照，不做增量同步。

### 目录规划

在保持现有结构前提下，建议增加：

```text
internal/netproto
  联机消息定义和编解码。

internal/session
  host/client 会话管理、连接收发、输入转发和快照订阅。
```

程序入口继续放在 `cmd/snake`，通过 CLI 参数选择运行模式。

### 分阶段实施顺序

第一阶段：

1. 补充 CLI 参数解析，支持单机、`--host` 和 `--join`。
2. 为 TUI 增加运行模式，分离单机驱动和联机驱动。
3. 将 `game.Engine` 扩展为 2 名玩家共享地图。
4. 增加最小网络协议和 host/client 会话。
5. 用完整快照驱动客户端渲染。

第二阶段：

1. 增加局域网房间发现和房间列表。
2. 增加断线检测、玩家槽位保留和重连恢复。
